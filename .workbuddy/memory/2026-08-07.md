# 2026-08-07 调试记录

## 调试 install.ps1（Windows PowerShell 部署脚本）

**现象**：脚本完全无法运行，PowerShell 报 `ParserError: 语句块或类型定义中缺少右“}”`，错误定位在 130 行 `function Install-Deps {`（实为连锁假错误）。

**两个根因（均已修复并验证 `-Help` EXIT=0）**：

1. **here-string 结束符不能带参数**：`Show-Success` 中写成
   `Write-Host @" ... "@ -ForegroundColor Green`
   PowerShell 要求 `"@` 必须**独占一行**，行尾跟其他字符会导致结束符失效，把其后所有代码（含各函数 `}`）吞进字符串，最终报“缺少右 }”。
   修复：用变量承接 heredoc，再把颜色单独传参：
   ```
   $successBanner = @"
   ...
   "@
   Write-Host $successBanner -ForegroundColor Green
   ```

2. **缺 UTF-8 BOM**：脚本含中文但无 BOM。PowerShell 5.1 用 `-File` 执行无 BOM 的 UTF-8 脚本时会误判编码，中文字节被解错，产生杂散字符破坏解析（同样表现为“缺少右 }”）。
   验证：内容相同、带 BOM 的副本可正常 `-File` 运行；无 BOM 的真实文件报错。
   修复：用 `Set-Content -Encoding UTF8`（PS5.1 默认带 BOM）重写文件，内容不变。

**调试要点（可复用）**：
- PowerShell `-File` 执行的编码判定 ≠ `Parser]::ParseFile` API（后者按 UTF-8 读，会“假通过”）。判断编码类语法错误时，务必用 `-File` 实际跑一遍，并对比“带 BOM 副本”是否通过。
- 解析器报“缺少右 }”且位置奇怪时，优先排查：(a) here-string `"@` 是否独占一行；(b) 字符串/heredoc 是否因编码或弯引号而未闭合，导致大段代码被吞。
- 本项目 PowerShell 环境 `ELECTRON_RUN_AS_NODE=1`，`npm run build`(tsc) 在当前环境实测能正常退出(code 0)，脚本里置空该变量的做法在此环境可行。

**遗留待确认**：默认 `RepoUrl` 指向 gitee（`https://gitee.com/areyi2014/cloud-ip-rotator-mcp.git`），HEAD 探测返回 404，运行时 `git clone` 是否可达需联网实测（smart-HTTP 的 HEAD 404 不一定代表 clone 失败）。
