## 彻底规避 config.toml 冲突：改用 Codex Profile 叠加层
- 用户提出：既然 config.toml 是冲突源头，能否不改这个文件。
- 调查 Codex 文档（learn.chatgpt.com/docs/config-file/config-advanced）发现：Codex 支持多层配置，其中 Profile 文件 `~/.codex/<name>.config.toml` 通过 `--profile <name>` 加载，叠加在 config.toml 之上，CC Switch 不碰这个文件。
- CLI 验证：`codex --help` 确认 `-p, --profile <CONFIG_PROFILE_V2>` 选项存在，描述为 "Layer $CODEX_HOME/<name>.config.toml on top of the base user config"；`codex --profile test app --help` 语法通过（全局选项在子命令前）。
- 方案实施：
  1. 创建 `~/.codex/ip-switch.config.toml`，含三段（marketplaces.local + plugins.ip-switch@local + mcp_servers.ip-switch）。
  2. 从 `~/.codex/config.toml` 删除全部 ip-switch 段，CC Switch 可自由管理。
  3. `codex_app.vbs` 启动行改为 `codex --profile ip-switch app`；install.sh 的 codex_app.sh 改为 `codex --profile ip-switch app`。
  4. 删除上一轮的 guard 守护进程（计划任务 + ps1/vbs/log 文件 + 运行中进程），不再需要。
  5. install.ps1/install.sh：Install-CodexPlugin 改为创建 profile 文件而非写 config.toml；Install-CodexMarketplace 不再写 config.toml 的 marketplaces/plugins 段。
- 优势：零冲突——CC Switch 改 config.toml 不影响 ip-switch；无需后台守护进程；无需改 cc-switch.db。
- 注意：用户必须通过 codex_app.vbs（桌面快捷方式）启动 Codex 才能加载 profile。如果从开始菜单或其他方式启动 Codex，不会加载 profile。

## 重大发现：--profile 不支持 codex app 子命令，改用 -c 覆盖
- 用户问 ip-switch.config.toml 能否自动加载。
- 调查结果（Codex v0.151.0-alpha.7.2）：
  1. `CODEX_PROFILE` 环境变量：二进制中不存在此字符串，实测不生效。
  2. `profile = "ip-switch"` 写入 config.toml：报错 "legacy config is no longer supported; use --profile with .config.toml instead"。
  3. `--profile ip-switch app`：报错 "--profile only applies to runtime commands and codex mcp"（app 不在支持列表中）。
  4. 结论：v0.151 中 **没有任何自动加载 Profile 的机制**，--profile 是唯一激活方式，且仅支持 codex/exec/review/mcp 等运行时命令，不支持 app/app-server。
- 替代方案：使用 `-c key=value` 配置覆盖（codex app 子命令接受 -c）。
  - `codex -c "mcp_servers.ip-switch.command='...'" -c "..." app` 实测成功启动桌面版且 ip-switch 出现在 MCP 列表。
  - 三段配置（MCP + marketplaces + plugins）均可通过 -c 传递，`codex -c '...' mcp list` 和 `codex -c '...' app` 均验证通过。
- 文件更新：
  1. `codex_app.vbs`：将 `--profile ip-switch app` 替换为 8 个 -c 覆盖标志 + `app`。使用 Chr(34) 处理 Windows 命令行双引号转义（特别是 plugins."ip-switch@local" 键）。
  2. `install.sh`：codex_app.sh 启动行从 `exec codex --profile ip-switch app` 改为 `exec codex -c "..." ... app`。
  3. `install.ps1`：函数注释和 Profile 文件创建注释更新为说明双重用途（Profile 供 CLI，-c 供桌面版）。
  4. Profile 文件 `ip-switch.config.toml` 保留——仍用于 `codex --profile ip-switch mcp list` 等 CLI 命令。
- 双重机制：CLI 命令用 `--profile ip-switch`（加载 profile 文件），桌面版用 `-c` 覆盖（内联配置）。两条路径互不干扰。

## ip-switch Codex 桌面版配置加载问题（已修复）

**问题**：重跑 install.ps1 后 Codex 桌面版的个人市场和 MCP 都不显示 ip-switch。

**根因**（经真实进程 cmdline 验证）：`codex app` 通过 `codex://` 协议 URL 拉起桌面版，VBS 里的 8 个 `-c key=value` 参数被 CLI 解析后**静默丢弃**，根本传不到桌面进程。桌面版只读 `~/.codex/config.toml`（被 CC Switch 清理）+ 工作区内项目级 `.codex/config.toml`。

**解决方案**（三层配置，均独立于 config.toml）：
1. `installDir/.codex/config.toml`（项目级配置层）——桌面版主要通道。以 installDir 为工作区启动 `codex app`，首次启动 Codex 自动写 `[projects] trust_level="trusted"` 信任条目，信任后 mcp_servers/marketplaces/plugins 全部生效（已实测 mcp list 和 plugin list 均显示 ip-switch installed/enabled）
2. `~/.codex/ip-switch.config.toml`（Profile 叠加层）——CLI 专用，`codex --profile ip-switch mcp list`（注意 --profile 必须在子命令**前面**，v0.151 中放在后面会报错）
3. `installDir/.mcp.json`——市场插件 plugin.json 引用

**关键验证**：
- `codex --profile ip-switch mcp list` ✓（--profile 需放子命令前）
- `codex app` 会自动信任 CLI 传入的工作区路径（自动写 projects 表）
- 项目级配置在未信任时被静默忽略

**修改文件**：codex_app.vbs（删 -c，改为 `codex app "<workspace>"`）、install.ps1（新增步骤 2.5 生成项目级配置）、install.sh（同步）、本机 C:/Users/Administrator/ip-switch/ 已同步。
