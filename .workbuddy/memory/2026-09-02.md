## 项目级 / Profile 文件各自该放什么（Codex 配置分层澄清）

## 决议：彻底移除项目级 .codex/config.toml 与 Profile ip-switch.config.toml
- 用户追问：`codex --profile ip-switch` 是什么命令，是否"定义全局配置"？
  - 澄清：`--profile <名>` 是**调用时选择命名预设**的开关（如 `codex --profile ip-switch mcp list`），只读不写，**不是全局配置**；真正的全局是 `~/.codex/config.toml`（无 profile）。桌面 `codex app` 不支持 --profile。
  - Codex profile 有两种机制：规范是 `[profiles.<名>]` 内联在 config.toml；我们用的独立文件 `~/.codex/<名>.config.toml` 仅一份 hardening cheatsheet 提及、官方文档未规范、未实证。
- 评估两份文件实用性 → 结论：**均不实用，对桌面流程零增益**：
  - 项目级 `.codex/config.toml`：桌面全局列表不读它；信任条目是 C 档（CC Switch 重启即清），脆弱。
  - Profile `ip-switch.config.toml`：仅 `codex --profile ip-switch` 加载，桌面不加载；独立文件机制未实证。
- 改动（两个脚本同步）：
  - `Install-CodexToml`/`install_codex_toml` 瘦身为**只调用** `Ensure-CodexUserConfig`/`ensure_codex_user_config`（用户级注册），删除项目级/Profile 模板生成。
  - sh 主流程删掉与 `install_codex_toml` 内重复的第 998 行 `ensure_codex_user_config` 调用。
  - 清理残留：Install-CodexMarketplace 内"市场注册已移至 Profile"陈旧注释、成功提示里的"项目级配置"行、卸载提示里的 profile/project 删除行、ensure_*_user_config 注释里的"项目级同名声明"措辞、codex_app.sh 生成函数注释、codex_app.vbs 注释里去"or a --profile config"表述。
  - 磁盘上两份文件已删除：`C:\Users\Administrator\ip-switch\.codex\config.toml`、`C:\Users\Administrator\.codex\ip-switch.config.toml`。
- 验证：bash -n install.sh 通过；install.ps1 用 PSParser Tokenize 解析通过；残留引用 grep 仅命中"说明性注释"（解释曾生成过这两文件），无死代码引用。
- 收益：单一事实来源收敛为**用户级 config.toml 注册**（marketplaces + plugins + mcp 三段），顺带根除"4 vs 3"幽灵计数。后续重装后桌面可见性只依赖用户级三段。
