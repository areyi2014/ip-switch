## 为 ip-switch 创建 ip-switch skill（WorkBuddy / Codex 通用唤起配置页）

### 需求
用户要求写一个 skill,让各种 AI agent（WorkBuddy / Codex）能直接唤起 ip-switch 的 MCP 配置页面;并完善 install.ps1 / install.sh 让它们自动安装该 skill。

### Skill 设计

**目录结构**（项目内 `skills/ip-switch/`,装到 `~/.workbuddy/skills/ip-switch/`）:

```
skills/ip-switch/
├── SKILL.md              ← frontmatter + 触发规则 + 调用说明
├── skill.json        ← display_name / description_zh|en
├── _icon.svg             ← IP Switch 图标（云 + 交换箭头）
└── scripts/
    ├── open-ui.mjs       ← 主脚本（Node.js 跨平台、零依赖）
    ├── open-ui.sh        ← Bash 包装器
    └── open-ui.ps1       ← PowerShell 包装器
```

**open-ui.mjs 核心逻辑**:
1. 读 `~/.ip-switch/install-dir.txt`（install 写入）→ 定位 ui/server.cjs
2. 读 `~/.ip-switch/server-port.txt` + TCP 健康检查 → 检测 server 是否在跑
3. 没跑则后台启动（Windows 用 `cmd /c start /B`,Unix 用 `detached+unref`）
4. 跨平台打开浏览器:`cmd /c start "" "<url>"` / `open` / `xdg-open`

**支持的页面**: 默认(`config-form.html`) + `aws` / `azure` / `oci` / `vultr` 各平台独立表单

**支持的模式**:
- `node open-ui.mjs [page]` —— 启动并打开浏览器（AI 主流调用）
- `node open-ui.mjs --port [page]` —— 只输出 URL 到 stdout,不打开（CI / 调试）
- `node open-ui.mjs --status` —— 输出 JSON 状态
- `node open-ui.mjs --stop` —— 关闭后台 server

### 关键坑（必须记住）

**Windows 进程脱离**: `detached: true + child.unref()` 在 Windows 上不够,父进程退出时子进程会被 job 对象回收。必须用 `cmd /c start /B node script.js` 才能真正脱离。这是 Windows 后台服务类脚本的通用解法。

## 同日调整：skill 名改为与 plugin 同名（`ip-switch`）

用户反馈 skill 名 `ip-switch-ui` 与 plugin 名 `ip-switch` 不一致,要求统一为 `ip-switch` 方便记忆。

**可行性**:
- skill 目录:`~/.workbuddy/skills/ip-switch/`
- MCP server 在 `mcpServers.ip-switch`
- 两者命名空间完全不同,**无冲突**

**改了什么**:
- `skills/ip-switch-ui/` → `skills/ip-switch/`
- SKILL.md `name: ip-switch-ui` → `name: ip-switch`
- `display_name: "IP Switch · 配置面板"` 用「· 配置面板」后缀区分(避免与 MCP plugin 列表混淆)
- install.sh / install.ps1 所有路径引用
- memory 中的旧引用同步更新

**为什么 display_name 要区分**:
WorkBuddy 的连接器管理页会同时列出 MCP plugin 和 skill;如果两者都叫 "IP Switch",用户难分哪个是哪个。display_name 加后缀是最小成本的可读性保证。
