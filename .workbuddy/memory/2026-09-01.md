## ip-switch 重装后 Codex 列表为空（信任表丢失，已修复）

**现象**：用户删除所有相关配置文件+toml 配置项后重跑 install.ps1，Codex mcp 列表/市场/插件列表均无 ip-switch。

**根因**：删除配置时连 `~/.codex/config.toml` 里的 `[projects.'c:/users/administrator/ip-switch'] trust_level="trusted"` 信任条目一起删了。Codex 对未信任工作区**静默忽略**项目级 `.codex/config.toml` → 项目级通道（桌面版+plugin 命令）全失效。Profile 通道（`codex --profile ip-switch mcp list`）一直正常。

**诊断要点**：
- `codex mcp list` 带不带 `--profile` / 在不在工作区内，结果完全不同
- `--profile` 只支持 runtime 命令和 `codex mcp`，`plugin marketplace list` / `plugin list` 子命令不支持，只能走项目级通道（需信任）

**修复**：备份 config.toml 后追加信任条目（仅 append projects 表，不碰其他配置）→ mcp list / marketplace list / plugin list 全部恢复。

**遗留建议**：install.ps1 可加"信任自动补写"逻辑（检测 config.toml 无 ip-switch 信任条目时备份+追加），否则每次重装/CC Switch 重写 config.toml 后信任丢失，项目级通道静默失效，排查成本高。

## 信任条目能否写入项目级 config.toml？（实测：不能，鸡生蛋问题）

**问题**：用户问 `[projects.'c:/users/administrator/ip-switch'] trust_level = "trusted"` 能否写进安装目录下 `~/.codex`（项目级）配置，避免 install 脚本写用户级 config.toml。

**实测结论**（真机验证，非猜测）：
1. 临时删除用户级 config.toml 的 ip-switch 信任条目，同时在 `~/ip-switch/.codex/config.toml` 里写入相同条目（"自信任"）
2. 工作区内 `codex mcp list` → 只有 cua_repl/node_repl，ip-switch 不加载
3. `codex plugin marketplace list` → local 市场消失（只剩 openai-bundled/openai-curated）
4. 恢复用户级信任条目 → ip-switch 立刻回来

**原理**：信任是启动引导（bootstrap）机制。项目级 `.codex/config.toml` 只有在项目**已被信任后**才会被读取——把信任条目放进项目级配置等于"自己证明自己可信"，Codex 直接忽略整个文件。信任条目**只能**存在用户级 `~/.codex/config.toml` 的 `[projects]` 表（或桌面版首次打开时的信任弹窗）。

**推论**：install.ps1 若想免手动信任，只能安全地「检测缺失 → 备份 → append 用户级 config.toml 的 projects 表」，不能指望项目级配置自举。`codex --help` 无 --trust-project 类 flag。

**坑/教训**：

## 根因修复：重装后 Codex 插件列表仍看不到 ip-switch（市场/插件注册只在工作区级）

**现象**：用户重跑 install.ps1 后，Codex 插件列表/marketplace 列表仍无 ip-switch（信任条目、marketplace 文件都正常）。

**真正根因**：插件与市场的注册（`[marketplaces.local]` + `[plugins."ip-switch@local"]`）只写进了：
- 项目级 `~/ip-switch/.codex/config.toml`（仅当打开的工作区恰好是 `~/ip-switch` 且已信任时才加载）
- Profile `~/.codex/ip-switch.config.toml`（仅 `codex --profile ip-switch` CLI 加载）
**没有写进用户级 `~/.codex/config.toml`**。桌面版 Codex 普通打开（非 ip-switch 工作区）只读用户级 config.toml → 无 local 市场声明 → 市场不被发现 → 插件列表空。这就是"重装后看不到"的本质。

**关键区分（写用户级 config.toml 是否安全）**：
- `model` / `mcp_servers` → 由 CC Switch 管理 → **绝不能**写用户级（会被改写）→ 此前用项目级/Profile 层规避，正确。
- `marketplaces` / `plugins` → **不由 CC Switch 管理**（SSOT 无这俩表）→ 写用户级**安全**，且只有写在这里插件才全局可见。

**修复**：
1. 直接在用户级 config.toml 追加 `[marketplaces.local]{source_type=local, source='~/.codex/marketplaces/local'}` + `[plugins."ip-switch@local"]{enabled=true}`（TOML 解析验证通过）。
2. install.ps1 新增 `Ensure-CodexUserConfig`（纯检测+追加，无备份）：检测 `[marketplaces.local]` / `[plugins."ip-switch@local"]` 缺失才追加；调用点 Install-CodexToml 步骤 2.4。
3. install.sh 新增 `ensure_codex_user_config`（bash 版，含 `/c/..`→`c:\..` 路径归一化）：调用点主流程 ensure_codex_trust 之后。
4. 项目级 / Profile 配置里的同名声明保留（作为该工作区/CLI 通道的冗余，无害）。

**验证**：PS1 函数落位(735-770 定义 / 853 调用)；SH 语法 `bash -n` OK，函数实测首次追加(/c/..→c:\.. 转换正确)/二次幂等跳过/不动 CC Switch 既有条目；本机 config.toml tomllib 解析 OK 且 marketplaces.local / plugins.ip-switch@local.enabled=True / 信任条目均存在。

**结论**：之后无论以何种方式打开桌面版 Codex，ip-switch 插件都在列表里；不再依赖必须通过 codex_app.vbs 以 ip-switch 为工作区打开。

## 实测推翻旧结论：CC Switch 重启会清空"手写"的 [projects] 信任条目（v3.20.0 实证）

**方法**（真机，零风险：先 cp 备份 config.toml → taskkill 结束 cc-switch.exe(6924) → 重新拉起 → diff）：
- 重启后 config.toml 被 CC Switch 在 12:58:17 重写。

**实测结果——CC Switch 是「部分重写/合并」，不是整文件覆盖，但各段行为不同**：

✅ **被保留（合并，不重置）**：
- `[marketplaces.local]` + `[plugins."ip-switch@local"]`（我们加的全局注册）原样存活
- `[mcp_servers.ip-switch]`（CC Switch 还**自动**根据本地市场里的 ip-switch 插件合成出了这段 mcp_servers —— 注意 db 的 mcp_servers 表只有 node_repl 一行，说明这是合并时按插件定义生成的）
- 其它非 SSOT 的 mcp_servers 段

❌ **被重置/重生成（每次重启按 CC Switch SSOT 重写）**：
- `model_provider` / `model` / `model_reasoning_effort` / `disable_response_storage` / `notify` / `model_catalog_json`
- `[model_providers.custom]`（整块；base_url 强制改回本地代理 `http://127.0.0.1:15721/v1`，`experimental_bearer_token="PROXY_MANAGED"`）
- `[marketplaces.openai-bundled]`、`[plugins."*@openai-bundled"]`、`[plugins."*@openai-curated"]`（bundled/curated 由 CC Switch 管）
- `[features]`、`[shell_environment_policy.set]`、`[windows]`、`[desktop]`
- `[mcp_servers.node_repl]`(+.env)（按当前 Codex runtime hash 重生成）；`[mcp_servers.cua_repl]` 甚至被丢弃
- `[projects.<cc-switch-已知工作区>]`（只重生成它认识的，例如 `documents\codex\2026-08-12\ne` 那条——**这就是之前误以为「CC Switch 不抹 [projects]」的来源**，那条是它的，不是手写的）

🔴 **手写 [projects] 信任条目会被清空**：我们手动加的 `[projects.'c:\users\administrator\ip-switch'] trust_level="trusted"` 在重启后被**删除**（diff 显示在文件末尾段被整段移除，且未在新位置出现）。

**对 install 设计的最终定论**：
1. ✅ 把 `[marketplaces.local]` + `[plugins."ip-switch@local"]`（及可选 `[mcp_servers.ip-switch]`）写进**用户级** config.toml 是**安全且正确**的——CC Switch 合并时保留，重启后 ip-switch 仍全局可见。这正是上一节修复采用的方向，已验证可存活。
2. 🔴 `[projects.'...ip-switch']` 信任条目**不可靠**：CC Switch 每次重启清空它。但**已无关紧要**——ip-switch 的可见性现在来自用户级全局注册（存活），不再依赖项目级 `.codex/config.toml` 被信任后才加载。
3. install.ps1/install.sh 的 `Ensure-CodexTrust` 可保留（幂等、无害、且若用户用 codex_app.vbs 以 ip-switch 为工作区打开时能让项目级配置也加载），但必须明白它是 best-effort、重启即失效；真正的持久机制是 `Ensure-CodexUserConfig` 的全局注册。
4. 旧日志(31-42行)"CC Switch 不会抹除 [projects]" 结论**需修正**：仅对 CC Switch 自己的已知工作区条目成立，对手写条目不成立。

**记忆机制**：上述三档分类已固化为项目长期记忆 `.workbuddy/memory/MEMORY.md`（跨会话存活，免重复实证）；install 脚本只把 B 档键写用户级 config.toml，已对齐，运行时不依赖记忆重测。
