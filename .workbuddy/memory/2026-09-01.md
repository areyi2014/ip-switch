# 2026-09-01

## ip-switch 重装后 Codex 列表为空（信任表丢失，已修复）

**现象**：用户删除所有相关配置文件+toml 配置项后重跑 install.ps1，Codex mcp 列表/市场/插件列表均无 ip-switch。

**根因**：删除配置时连 `~/.codex/config.toml` 里的 `[projects.'c:/users/administrator/ip-switch'] trust_level="trusted"` 信任条目一起删了。Codex 对未信任工作区**静默忽略**项目级 `.codex/config.toml` → 项目级通道（桌面版+plugin 命令）全失效。Profile 通道（`codex --profile ip-switch mcp list`）一直正常。

**诊断要点**：
- `codex mcp list` 带不带 `--profile` / 在不在工作区内，结果完全不同
- `--profile` 只支持 runtime 命令和 `codex mcp`，`plugin marketplace list` / `plugin list` 子命令不支持，只能走项目级通道（需信任）

**修复**：备份 config.toml 后追加信任条目（仅 append projects 表，不碰其他配置）→ mcp list / marketplace list / plugin list 全部恢复。

**遗留建议**：install.ps1 可加"信任自动补写"逻辑（检测 config.toml 无 ip-switch 信任条目时备份+追加），否则每次重装/CC Switch 重写 config.toml 后信任丢失，项目级通道静默失效，排查成本高。

## 信任条目能否写入项目级 config.toml？（实测：不能，鸡生蛋问题）

**问题**：用户问 `[projects.'c:/users/administrator/ip-switch'] trust_level = "trusted"` 能否写进安装目录下 `~/.codex`（项目级）配置，避免 install 脚本写用户级 config.toml。

**实测结论**（真机验证，非猜测）：
1. 临时删除用户级 config.toml 的 ip-switch 信任条目，同时在 `~/ip-switch/.codex/config.toml` 里写入相同条目（"自信任"）
2. 工作区内 `codex mcp list` → 只有 cua_repl/node_repl，ip-switch 不加载
3. `codex plugin marketplace list` → local 市场消失（只剩 openai-bundled/openai-curated）
4. 恢复用户级信任条目 → ip-switch 立刻回来

**原理**：信任是启动引导（bootstrap）机制。项目级 `.codex/config.toml` 只有在项目**已被信任后**才会被读取——把信任条目放进项目级配置等于"自己证明自己可信"，Codex 直接忽略整个文件。信任条目**只能**存在用户级 `~/.codex/config.toml` 的 `[projects]` 表（或桌面版首次打开时的信任弹窗）。

**推论**：install.ps1 若想免手动信任，只能安全地「检测缺失 → 备份 → append 用户级 config.toml 的 projects 表」，不能指望项目级配置自举。`codex --help` 无 --trust-project 类 flag。

## 修正：CC Switch 不会修改/抹除 [projects] 信任表（实证）

**问题**：用户问"CC Switch 不会修改 [projects] 项？"——质疑 install 脚本在 config.toml 追加信任条目的安全性。

**实证结论**（真机，非猜测）：
1. CC Switch SSOT 数据库 `~/.cc-switch/cc-switch.db`：providers 表（Zhipu GLM：model/auth/modelCatalog）、mcp_servers 表（只有 node_repl）——**没有任何 projects 数据源**
2. 本机 CC Switch 10:07 代理接管重写 config.toml 后，`[projects.'c:/users/administrator/documents/codex/2026-08-12/ne']`（非其管理的键）**完好存活**；[plugins]/[features]/[windows]/[desktop]/node_repl.env 等非管理键也全部保留
3. 与官方设计一致：cc-switch 是 SSOT 投影模型，"Live updates merge into existing files rather than overwriting, preserving unrelated local settings"

**修正旧判断**：8-31 日志中"CC Switch 改写导致 ip-switch 信任丢失"的判断**不准确**。真相：ip-switch 当时从未被信任过（初始安装未通过 codex app 启动触发自动信任），ne 条目一直存活恰好证明 CC Switch 不抹信任表。9-01 丢失是用户手动删除"toml 相关配置项"时误删。

**推论**：install.ps1 在 config.toml 追加 [projects] 信任条目是安全的（CC Switch 不会动它）；补写逻辑仍建议加，但防的是「用户手动删除」而非 CC Switch。

## install.ps1/install.sh 增加「Codex 信任自动补写」（已实现+测试通过）

**背景**：用户确认应在安装脚本中检测 ~/.codex/config.toml 是否存在 [projects.'...'] trust_level="trusted" 信任条目，缺失则补写（防用户手动删除/重装后项目级配置静默失效）。

**实现**（幂等，备份优先）：
- install.ps1 新增 Ensure-CodexTrust 函数（独立、参数化 $CodexConfig + $WorkspacePath）：检测 [projects.'<小写反斜杠路径>'] + trust_level，已存在跳过；缺失则先 Copy-Item .bak-时间戳 备份，再 AppendAllText 追加（UTF-8 无 BOM），仅追加 [projects] 子表，不修改其他任何配置
- install.sh 新增 ensure_codex_trust 函数（bash 版，用 [[ == [a-z]:* ]] 区分 Windows 盘符路径→反斜杠 / POSIX 路径→正斜杠）
- 调用点：Install-CodexToml 步骤 2.3（生成项目级配置+Profile 叠加层之后）/ install_codex_toml 步骤 3.5
- 卸载提示补充「可选: 删除 ~/.codex/config.toml 的 [projects] 信任条目」

**测试**（真机，从仓库 install.* 提取真实函数源码 dot-source 测试）：
- PS 版：模拟缺失→补写成功；再次调用→幂等跳过；Python tomllib 验证 TOML 合法、ne 条目保留、mcp_servers(node_repl/cua_repl) 保留 ✓
- bash 版：Windows 路径幂等 / POSIX 路径补写 / 幂等 / config 不存在安全跳过 四场景全过 ✓

**坑/教训**：
1. PowerShell 工具 stdout 经常被吞——结果必须写文件再用 bash cat 读
2. Invoke-Expression 被 PowerShell 工具安全策略拦截——改用「提取函数到临时文件→dot-source」
3. Git Bash heredoc 中反斜杠路径会被 MSYS 转换——测试数据用 Write 工具写入避开
